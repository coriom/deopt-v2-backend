## Proxy 8080 : correctif préparé, non appliqué

La configuration persistante est gérée dans **Coolify → Servers → localhost → Proxy → Configuration**. Le fichier `/data/coolify/proxy/docker-compose.yml` est une sortie générée et peut être réécrit au redémarrage ; une édition isolée du fichier ne constitue pas le correctif durable ([documentation officielle](https://coolify.io/docs/core/networking/proxy/traefik/overview)). Les contrôles opérateur antérieurs indiquent `api.insecure=false`, aucun entrypoint 8080 et 80/443 publiés. La nécessité du port 8080 pour d'autres applications reste à confirmer sur la configuration sauvegardée.

Avant toute modification réseau, exporter la configuration **sauvegardée dans l'UI**, conserver sa copie intégrale et son SHA-256 sous contrôle opérateur. Retirer uniquement les entrées `ports` publiant l'hôte 8080 en IPv4 ou IPv6. Conserver les ports 80/443, les réseaux, routes, labels, volumes, image et commandes. Valider le Compose candidat et comparer le diff, qui ne doit toucher que ces entrées. Le changement et le redémarrage du proxy exigent une autorisation distincte. Après ce changement : contrôler les sockets et accès 80/443, les applications existantes, le tunnel 8000, puis l'absence d'écoute 8080. Si un contrôle échoue, restaurer **la copie sauvegardée dans l'UI**, redémarrer le proxy et répéter tous les contrôles. Le test local `test_proxy_8080_plan.py` valide seulement la transformation des mappings et le retour arrière de fixture ; il ne prouve pas un rollback réel sur Netcup.

## Sauvegarde PostgreSQL DeOpt

`deploy/vps/backup-offsite.sh` possède maintenant un mode Coolify : un projet Compose revu et **un seul** conteneur `postgres` doivent correspondre, avec l'image PostgreSQL 16 épinglée. Le dump est chiffré avant `rclone copyto`, puis le ciphertext distant est relu et son SHA-256 comparé. Le mode historique Compose demeure disponible. Le script n'expose pas PostgreSQL et ne lit aucune clé privée de signature blockchain.

`deploy/vps/restore-offsite-drill.sh` n'accepte qu'une base nommée `deopt_*_test` sur `localhost`, `127.0.0.1` ou `::1`, préexistante et vide ; il déchiffre en flux vers `pg_restore --single-transaction --exit-on-error`. Un succès de commande exige encore une **comparaison logique** indépendante des tables, comptes, fills et checkpoints. Les anciens drills locaux ont validé une restauration synthétique ; ils ne constituent pas une restauration du futur backup DeOpt hébergé. Il manque une destination hors VPS approuvée, la garde indépendante de la clé GPG, rétention/alerte, un premier upload chiffré et un restore isolé réel. La sauvegarde de la base interne Coolify ne les remplace pas.

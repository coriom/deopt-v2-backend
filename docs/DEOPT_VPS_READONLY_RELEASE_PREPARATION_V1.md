# DeOpt first VPS release: read-only preparation

Scope: one future Netcup x86-64 VPS (4 vCore, 8 GB RAM, 160 GB SSD), Base Sepolia 84532. This commit does **not** deploy to a VPS or enable trading. The deployable surface in this profile is deliberately narrow: `/health`, `/ready`, and `/perps/markets*`. With `PERPS_READ_ENABLED=false`, unavailable market data remains unavailable. Wallet fee history is **not** exposed: the current `/accounts/:address/perps/canonical-fees` endpoint selects an address from a URL without its own caller-authentication proof. CORS is no authorization control. A separate wallet-authenticated API review is required before exposing account history.

## Release files and boundary

- `compose.vps-readonly.yml`: PostgreSQL 16 on an internal Docker network and persistent volume; non-root Rust backend with read-only root filesystem, dropped capabilities and no published port; Caddy alone publishes 80/443. Backend health checks use `/ready`, separately from `/health`; neither indicates trading authorization. The three registry images are supplied by immutable digest. Limits are provisional, not a capacity guarantee. Container logs rotate at 10 MB × 5 files each.
- `deploy/vps/Caddyfile`: HTTPS for an operator-approved domain, plus a proxy-level mutation-method block. The Rust `DEOPT_READ_ONLY_RELEASE=true` guard independently refuses all non-GET/HEAD/OPTIONS methods and all routes outside the narrow allowlist. Startup rejects non-84532 chain identifiers, signing-material environment variable names, and any enabled worker/execution flag except persistence and optional read-side market access. The Compose profile keeps market reads and indexation off at first launch.
- `deploy/vps/backend-entrypoint.sh`: creates the PostgreSQL URL from a host-only Docker secret at container runtime. No password enters the image or Compose interpolation. Password must be URL-safe. Do not print `DATABASE_URL`, run `docker inspect` output into evidence, or commit host files.
- `deploy/vps/deploy-readonly.sh`: `--check` is local-only. Future `--execute` requires a separate explicit approval, exact host/user/path, pinned SSH known-host entry and key, and a digest-pinned backend image. It stages static files, locks the remote deployment, verifies Compose plus `/health` and `/ready`, and records the previous image. Economic readiness and production acceptance still require a separate review. It does not downgrade migrations or roll back the database automatically.
- `deploy/vps/backup-offsite.sh`: PostgreSQL custom-format backup encrypted to a reviewed GPG recipient before an `rclone` off-server upload. This cannot operate until an off-server destination, recipient public key, host-only PostgreSQL service file and `rclone` installation are chosen. A successful upload is not a restore proof.

The host-only `release.env` must set **names and paths only**: `DEOPT_BACKEND_IMAGE`, `DEOPT_POSTGRES_IMAGE`, `DEOPT_CADDY_IMAGE` (registry digests), `DEOPT_DOMAIN`, `DEOPT_CORS_ORIGIN` (the reviewed HTTPS frontend origin) and `DEOPT_POSTGRES_PASSWORD_FILE` (absolute host path). Keep `release.env` and the password file mode 0600, outside Git. The password file must be owned by numeric UID 1001 so the non-root Rust container can read the file-backed Compose secret; the local drill confirmed that mode 0600 with host UID 1000 caused startup failure. Restrict its parent directory appropriately and never print its contents. Do not put signing keys, wallet secrets, or public-broadcast flags on the host. The image registry and domain are **not selected here**.

## Operator workflow after separate authorization

1. Provision the VPS and SSH key-based operator access. Pin the host key out of band. Open a **second independent key-based SSH session** and verify it works before disabling the initial password/root access path. Keep a recovery console available.
2. Install Docker/Compose, host-only release files and database secret, a reviewed registry image digest, and approved DNS/TLS domain. Restrict SSH and expose only the proxy ports; never expose PostgreSQL or the Docker socket.
3. Review `release.env` permissions and `docker compose config -q` without printing expanded configuration. Run `deploy-readonly.sh --check` locally. A separately authorized operator may then run `--execute` with the exact host and reviewed key.
4. Verify `/health` 200, `/ready` semantics, write methods 405, wallet-history 403, no fabricated markets, no signing keys, broadcaster/workers off, and the actual deployed image digest. `/health` alone is not trading readiness.
5. For rollback, inspect `.previous-image`, independently verify migration compatibility and backup state, then reapply that digest through a new approved deployment. Never downgrade PostgreSQL or migrations automatically.

Backups: use an off-server repository with its own retention policy and monitor upload failures. Test a restore into an empty disposable database before relying on it. The existing `scripts/alpha_pg_restore_drill.sh` checks logical state and duplicate replay for test-only DB names; the new encrypted off-server transfer remains unverified until a recipient/destination is selected. `debug_traceTransaction` with `callTracer` must be demonstrated on a provider able to return canonical nested traces before authenticated wrapped-fill reconciliation is hosted; the public Base Sepolia endpoint returned HTTP 401 for the bounded probe. Keep provenance fail-closed if unavailable.

## Bounded local evidence and release limits

The disposable PostgreSQL 16 instance applied 71 migrations. A 15.16-second loopback sample of 131 `/health` requests returned 200 throughout: p50 11.99 ms, p95 24.91 ms; the Rust process grew from 34.47 to 39.94 MiB RSS and consumed 1.74 CPU seconds. A separate PostgreSQL idle sample was 97.26 MiB and 0.15% CPU. A pristine database occupied 7,537,167 bytes; the migrated synthetic source occupied 13,466,647 bytes, a 5,929,480-byte difference. These figures cover startup, schema, synthetic checkpoint and health traffic. They **do not** establish peak multifill/replay resource use, storage growth over time, or that an 8 GB VPS is sufficient.

The backend returned `/ready` 200, `/perps/markets` 503 (market reads off), wallet fee history 403 and order submission 405. It shut down on SIGTERM with exit 0, restarted against the same disposable database and retained all 71 migrations. The focused signed-origin/fee PostgreSQL test ran against a disposable database and passed; seven receipt/fee unit tests and two read-only guard tests passed. These are local results only.

The actual release Dockerfile built successfully (optimized Cargo phase 40m 37s on the shared local host). In a separate disposable Compose project, the image ran as UID 1001 with a read-only root filesystem and all capabilities dropped, with no backend or PostgreSQL host port mapping. It returned the same 200/503/403/405 status pattern, restarted healthy, and retained 71 migrations. A single idle `docker stats` sample showed backend 19.45 MiB / 2 GiB at 0.01% CPU and PostgreSQL 56.54 MiB / 1.5 GiB at 0.02% CPU. These are idle container samples; the image is a local tag, not yet a published registry digest. The first Compose attempt failed because the host-owned mode-0600 secret was unreadable by UID 1001; the corrected ownership contract passed on rerun.

The existing two-fill receipt/fee/replay test group ran with a disposable PostgreSQL URL: 7/7 passed, Rust test execution 17.41 seconds; the surrounding `cargo test` process took 32.42 seconds wall time and peaked at 99,028 KiB RSS. This measures the local test process, **not** a persistent API plus indexer under continuous market load.

The local `alpha_pg_restore_drill.sh` passed with logical checksum `d569415f1a79a04618f45a7d2eecce33` and no duplicate replay effect. Separately, a GPG-encrypted custom-format dump was restored into another empty disposable database and its source/target checkpoint matched. The encrypted file was 41,904 bytes. The off-server upload, retention and alerting remain unverified.

No production hosting decision follows from this sample. Before deployment, select the image registry, TLS domain, off-server backup destination and trace-capable Base Sepolia RPC; confirm resource headroom under a representative persistent multifill/replay workload; authenticate any account-history endpoint before exposure. Strict repository-wide Clippy and formatting gates remain unresolved and must be reported accurately before release acceptance.

See the accompanying acceptance manifest for commands, fresh local outcomes and the exact verification boundaries.

# DeOpt local perps alpha: concurrency and recovery checkpoint

This checkpoint is local only. Public order intake, public transaction broadcasting, and Base Sepolia governance remain disabled. The isolated Anvil fixtures simulate contract states and do not represent public fills.

## Implemented changes

- The in-memory submit path fetches the oracle quote before taking order and position locks. It clones both ledgers, rechecks reduction and quote freshness at the commit boundary, and swaps both only after a successful mutation. A delayed quote cannot hold either shared mutex or commit against stale orderbook state.
- An ordinary opposite-side order still needs a fresh quote and opening-risk checks because it may rest and later become an increase. Only an explicit reduce-only order may bypass the oracle freshness gate, and its entire requested size must fit the current position before it can rest.
- Matching rejects a self trade across the entire planned fill set before changing any maker. Equal-price/equal-time makers have a stable UUID tie breaker.
- PostgreSQL submit, cancel, funding, and liquidation transactions take one transaction-scoped advisory ledger lock. The serialized transaction reads current positions and orders, rechecks risk caps and quote freshness, then assigns time priority and commits atomically. This conservative global lock favors correctness over throughput for the local alpha; it is not a scaling claim.
- PostgreSQL order, fill, position, funding, and liquidation persistence now carries subaccount IDs. Liquidation cancels only the liquidated subaccount's orders; client-order idempotency matches the database key `(account, subaccount, client_order_id)`.
- A PostgreSQL full-position close now updates only the requested subaccount. The new regression closes subaccount 2 while the same wallet's subaccount 1 remains open.
- `/ready` distinguishes process/data serviceability from `perps_market_data_status` and `perps_trading_status`. A 200 response is not trading authorization.
- The in-memory registry test reader now classifies a forced RPC failure as registry-unavailable, matching the production reader. An absent market remains a distinct not-found case; this corrected a library test that previously confused those outcomes.
- The local Compose profile binds the backend to loopback, keeps PostgreSQL private, runs with broadcaster and public trading disabled, and uses a read-only backend filesystem. The image build is limited to one Cargo job and uses BuildKit registry/target caches for bounded retries, copying only the finished binary into the runtime image. `.dockerignore` excludes historical `.env*` files from the build context.
- The first image exposed a real lifecycle defect: Docker SIGTERM was not observed because the server only awaited Ctrl+C. The server now accepts SIGTERM, drains HTTP connections for at most five seconds, then applies the existing bounded worker shutdown. `scripts/test_backend_sigterm_shutdown.py` checks a real local child process exits cleanly after SIGTERM.

## Acceptance limit

The local concurrency and recovery paths are materially better tested, but this is not a public perps alpha acceptance. In-memory state is transient across process restarts; even an accepted in-memory order disappears with that process. PostgreSQL is required for durable orders, and an interrupted PostgreSQL transaction rolls back rather than becoming a visible fill. The PostgreSQL global ledger lock is conservative and has not been load-tested for production throughput. The isolated Anvil lifecycle uses synthetic accounts and locally altered maintenance state. It does not prove that the currently maintained Base Sepolia contracts can execute trades. Fresh signature/replay, reorg/indexer, margin, Docker runtime, and hosted-failure evidence must be read alongside the final acceptance manifest; any uncompleted gate remains explicit there.

The backend's existing `launch_fee_schedule()` is also not the approved, still-unexecuted Base Sepolia D2 policy: its PERP tier 0 is 0.5 bps maker / 3 bps taker, and higher tiers contain positive maker rebate rates. Rebate accrual has separate eligibility gates; those configured rates alone do not prove a current liability. The approved future testnet policy is 0 bps maker / 2 bps taker / zero rebate in all five tiers. This checkpoint does not silently switch a runtime ledger to an unexecuted on-chain policy. A separate fee-source synchronization gate must read canonical D2 profiles after their individual S2 postflights, preserve existing legacy liabilities, and refuse perps fee accounting if the effective profile is unavailable or mismatched. This is a material remaining local-alpha blocker, even while public trading is disabled.

On the public chain, C02 market creation and the six D2/D3 executions remain separate operator-controlled governance actions. C02 is not authorized for execution, market 1 is not assumed to exist, D4/D6 maintenance stays in force, and no backend public broadcaster is enabled.

The next implementation gate is a fail-closed fee-source check: after separate canonical D2 S2 postflights, read the five live D2 PERP profiles and permit fee accounting only when they agree with the approved 0/2/0 bps policy. Until then, matching fixtures are local simulations, not a public fee source. A separate recovery gate still needs durable indexer replay/reorg testing and a restored PostgreSQL backup; the synthetic crash sample and local container restart do not prove those hosted properties.

## Future hosting boundary

For a disposable local rehearsal, supply a new local-only `DEOPT_ALPHA_DB_PASSWORD` in the invoking shell and run `docker compose -f compose.alpha-local.yml up --build`. The backend binds only to `127.0.0.1:18080`; PostgreSQL is not published. Stop with `docker compose -f compose.alpha-local.yml down` and retain the named volume only while the recovery rehearsal needs it. Never reuse a production database password in this profile.

Keep Vercel as the independently deployed frontend. A future Rust matching service needs a persistent Docker process, PostgreSQL with backed-up volume, supervised indexer/workers, bounded logs, `/health` liveness and `/ready` serviceability probes, cursor/worker alerts, RPC failover, and tested database restore. A small VPS running the reviewed Compose stack is the simplest controllable alpha host; managed containers are also viable if they keep workers persistent and use a durable external database. Vercel Functions are suitable only for a stateless gateway, not the matching ledger or indexer. Pin the image digest and migration revision. Rollback must consider automatic SQL migrations and reprocess chain events idempotently from a verified checkpoint. No remote service is provisioned or started by this checkpoint.

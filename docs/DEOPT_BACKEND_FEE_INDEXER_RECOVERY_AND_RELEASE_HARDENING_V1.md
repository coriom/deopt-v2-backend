# DeOpt backend fee source and recovery candidate

This milestone changes only the local Rust backend. It did not execute a public transaction, deploy a remote service, or enable a broadcaster.

## Fee source

The existing `fees::schedule` is a legacy local launch table. It does not represent the approved replacement D2 PERP policy. D2 stores signed **ppm** rates: the separately governed `setFeeProfile(tier, PERP, 0, 200)` means 0 bps maker and 2 bps taker. D2 rounds positive charges up using `Math.mulDiv(..., Rounding.Ceil)`. Its `currentTier(account)` reads D2 claimed-tier state and expiration, not the backend rolling-volume table.

`fees::d2_onchain` now reads D2 at one safe block hash and validates chain 84532, the canonical D2 address and runtime hash, owner, recipient, rebate funding account, fee-vault hook, five PERP profiles and five RFQ discounts. The account-tier reader uses the same pinned block hash. The execution-proof function requires five distinct successful canonical receipts with exact `ProtocolTimelock.TransactionExecuted` operation IDs, plus consumed queue entries. A full fee-policy proof is constructed only after both checks; it never grants trading eligibility by itself.

The existing indexed V2 PERP fee-accrual path now **rejects** replacement trades before applying the legacy schedule. This intentionally leaves replacement fee accounting unavailable until a separately reviewed integration uses the verified D2 fee policy end to end. Historical V1 fee accounting is unchanged. No locally approved policy is treated as executed. All six D2/D3 S2 operations still require their own canonical public postflights; ETA alone is insufficient.

## Indexing and recovery

The legacy PERP indexer now stores a canonical block hash with its cursor and rejects a cursor with an absent or divergent hash. It checks the RPC chain ID, the batch-end block hash before and after log retrieval, every log's canonical block hash, and out-of-range logs. Each HTTP RPC request has an eight-second timeout. Cursor compare-and-swap and trade insertion share one PostgreSQL transaction under an advisory lock. A legacy cursor created before this migration stays unbound and requires explicit reconciliation; the process must not guess a hash or advance it.

The legacy indexer **stops** on a detected reorg. It cannot yet safely rewind downstream fee events or other consumers; its old indexed rows may require manual reconciliation. This is a deliberate fail-closed boundary, not a claim of automatic legacy recovery. The separate Hybrid V2 canonical journal already implements persisted orphan invalidation, canonical replay and restart-safe recovery; its focused real-PostgreSQL recovery suite passed 9/9 tests in this milestone.

## Disposable PostgreSQL restoration

The new `scripts/alpha_pg_restore_drill.sh` accepts only two distinct `deopt_*_test` databases and refuses a nonempty restore target. It takes a real custom-format `pg_dump`, restores with `pg_restore --exit-on-error`, compares source and restored logical-state digests for orders, PERP orders/fills/positions, indexed trades, cursor and fee events, then repeats an indexed-trade insert with conflict protection to prove duplicate replay leaves the state unchanged. The temporary archive is removed on exit. Synthetic fixture SQL is in `tests/fixtures/alpha_restore_synthetic.sql`; no database dump or credential is committed.

The local drill used a newly created disposable PostgreSQL 16 container, a dedicated indexer source database, and a separate empty restore database. The restore digest matched (`65733b7d9fe096f67b240e92d6c2aca1`) and duplicate replay made no change. The restored database held one legacy order, two PERP orders, one fill, one position, one indexed trade and a block-2 canonical cursor. The final local Docker image started against that restored database as a non-root user with a read-only filesystem. `/health` and `/ready` returned 200; readiness explicitly reported market data and trading disabled, while `/perps/markets` returned 503. Restarting the backend container preserved those states and all restored record counts. `/ready` means the process/config/database are serviceable; it is not a trading authorization.

## Release boundaries and next gate

The smallest practical future host is a persistent Docker service for the Rust API/indexer, a managed PostgreSQL database with tested backups, supervised workers and monitored health/readiness. Vercel remains the frontend host. The existing `compose.alpha-local.yml` is a loopback-only rehearsal profile; it is not a production deployment manifest. Before hosting, the operator needs a private network for PostgreSQL, authenticated API and metrics exposure, immutable image tags, external secret injection, backup retention plus a restore drill, RPC health/failover, bounded worker restart policy, and a rollback that stops the API and workers before restoring a known compatible image and database checkpoint. `/health` is process liveness; `/ready` checks serviceability and its `perps_trading_status` must still be read separately. The backend must keep transaction submission disabled until a separate public-trading authorization and verified governance, market, migration, ACL and emergency-state gates pass. No cloud host was provisioned here.

**Validation:** focused fee tests 112/112, Hybrid V2 PostgreSQL reorg tests 9/9, and the legacy indexer PostgreSQL cursor test 1/1 after the final timeout patch. The final release Docker image built and passed the restored-database runtime checks above. Strict `cargo clippy --lib -- -D warnings` fails with 197 diagnostics from the existing library surface; none point into the new D2 reader or changed indexer paths. Repository-wide `cargo fmt --check` also fails on preexisting formatting drift, so only new files received targeted formatting checks. These are unresolved quality gates, not passes. Prior local Anvil and frontend browser results were reused rather than rerun for this fee/indexer change.

**Remaining local release gates:** integrate the verified D2 account-tier and fee quote into the replacement fee accrual path, add a canonical reorg-safe legacy fee-ledger reconciliation procedure, and close strict lint/format debt. Re-run connected browser and isolated Anvil acceptance after any runtime integration. Replacement V2 fee accrual and automatic legacy-indexer reorg rewind remain blocked rather than being presented as complete.
